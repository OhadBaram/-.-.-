# מצב קיים מול מצב סופי

## 1. הנחת יסוד

כל החלטה במעבר נמדדת בשאלה אחת:

> האם המשתמש מגיע מהר יותר לקרוסלה שמרגישה «שלו» וניתנת להורדה — בלי להשאיר stubs, מסכים מתים, או נתיבים כפולים בקוד?

אם התשובה לא חד־משמעית — לא מכניסים את השינוי למסלול הראשי.

---

## 2. מצב קיים (As-Is)

### 2.1 רצף משתמש בפועל

```
התחברות (Google)
  → שער פרופיל: חובה name + phone
  → אונבורדינג 3 שלבים (פרטים / קישורים / ניתוח מותג)
  → /dashboard/create
  → CreationWizard:
       נושא (צ׳אט) → המלצות + הגדרות סופיות
       → כיווני תוכן → «צור חבילה»
  → SkeletonLoader
  → מסך «החבילה מוכנה» (explanation + כיתוב + האשטאגים)
  → CarouselRenderer (עורך)
  → העלאת תמונה ידנית לכל שקף (SlideEditor)
  → הורדה: ZIP ו/או PDF (אותו קנבס 1080×1350)
```

### 2.2 מקורות אמת בקוד

| אזור | קבצים מרכזיים | התנהגות |
|------|----------------|---------|
| שער אונבורדינג | `src/app/dashboard/layout.tsx` | בלי `name`/`phone` → הפניה לאונבורדינג |
| אונבורדינג פרופיל | `src/app/dashboard/onboarding/page.tsx` | 3 שלבים לפני יצירה |
| תזמור יצירה | `src/components/CarouselCreator.tsx` | אשף / טעינה / סיכום חבילה / עורך; טיוטה נשמרת בחזרה לאשף |
| אשף | `src/components/CreationWizard.tsx`, `src/lib/wizard.ts` | צ׳אט + פאנל הגדרות + כיוונים |
| יצירה | `src/app/api/generate/route.ts`, `src/lib/validations.ts` | טקסט/סגנון/פלטה — **אין** שדה תמונה בבקשה |
| עורך | `src/components/CarouselRenderer.tsx` | קנבס קבוע; מובייל עם לשוניות תצוגה/עריכה (ב־PR נפרד) |

## 3. מצב סופי (To-Be)

### 3.1 הגדרת הצלחה חווייתית

המשתמש החדש:

1. נכנס ליצירה תוך מינימום שערים.
2. בוחר יעד פרסום (או מקבל ברירת מחדל).
3. כותב נושא אחד.
4. (אופציונלי) מעלה תמונה אחת.
5. מקבל עורך עם תצוגה מקדימה מיד.
6. מחליף placeholders בלחיצה על השקף.
7. מוריד בפורמט שמתאים ליעד.

**רגע ה־Aha:** קרוסלה עם לפחות תמונת משתמש אחת (או הבנה ברורה שאפשר להוסיף בלחיצה) + הורדה אפשרית תוך דקות.

### 3.2 רצף יעד — מסלול מהיר (ברירת מחדל)

```
התחברות
  → שער מינימלי (רק אם חסר מזהה בסיסי שחוסם שימוש)
  → /dashboard/create — מסלול מהיר:
       [0] יעד פרסום (instagram | linkedin) — ברירת מחדל: instagram
       [1] נושא (+ פרומפטים מהירים; צ׳אט = «עזרה לנסח»)
       [2] תמונה אחת אופציונלית / דילוג
       [3] יצירה → עורך ישירות (בלי מסך שער חובה)
  → עריכה קצרה (טקסט / החלפת תמונה / סדר)
  → הורדה לפי יעד
  → הזמנה רכה: שמירת מותג (פלטה / לוגו) — לא חוסם
```

### 3.3 מה נשמר מהקיים (לא לזרוק)

| רכיב קיים | החלטה | סיבה |
|-----------|--------|------|
| צ׳אט ייעוץ באשף | נשמר כמסלול «עזרה לנסח» | ערך למשתמשים שצריכים ניסוח; לא חוסם מהירים |
| פאנל «הגדרות סופיות» | עובר ל«מתקדם» אחרי קרוסלה ראשונה / מאחורי קישור | מפחית עומס; לא מוחק יכולת |
| כיווני תוכן | אופציונלי במסלול מתקדם; במסלול מהיר — כיוון ברירת מחדל מהשרת | שומר איכות בלי שלב חובה |
| שמירת טיוטה בחזרה לאשף | נשאר | כבר פותר כאב אמיתי |
| לשוניות תצוגה/עריכה במובייל | נשאר (אחרי מיזוג ה־PR הרלוונטי) | תנאי בסיס לתצוגה מקדימה |
| פלטת מותג דינמית | נשארת; לא במסלול המהיר הראשון | PLG אחרי הצלחה |
| `coverFitRect` + מיקוד עליון | נשאר כברירת התאמת תמונה | התנהגות טובה כבר קיימת |
| ייצוא ZIP + PDF | נשארים; CTA ראשי לפי יעד | אין לשבור משתמשים קיימים |

### 3.4 מה משתנה מהותית

| נושא | As-Is | To-Be |
|------|-------|-------|
| תמונה בזרימה | רק בעורך | העלאה מוקדמת + placeholder לחיץ בעורך |
| אחרי generate | מסך explanation חובה | כניסה לעורך; explanation כבאנר/מגירה |
| יעד פלטפורמה | משתמע מכפתורי הורדה | שדה מפורש בחוזה יצירה |
| stubs | `screenshots`, AI תמונה | מוסרים מהמסלול הראשי עד מימוש מלא |
| פורמט קנבס | קבוע | נגזר מ־`publishTarget` (עם מיפוי מרכזי אחד) |

### 3.5 מדדים

| מדד | הגדרה | כיוון יעד (ראשוני) |
|-----|--------|---------------------|
| `time_to_first_download` | מהכניסה ל־`/create` עד הורדה ראשונה | ירידה ברורה מול היום |
| `pct_with_user_image` | קרוסלות עם ≥1 `imageUrl` משתמש לפני הורדה | עלייה חדה |
| `create_to_editor_rate` | התחלת יצירה → הגעה לעורך | עלייה; פחות נטישה באשף |
| `explanation_gate_skip` | אחוז שנכנסים לעורך בלי אישור מסך ביניים | → ~100% במסלול החדש |
| `stub_cta_clicks` | לחיצות על כפתורי «בקרוב»/alert | → 0 אחרי ניקוי |

מדידה טכנית: אירועי אנליטיקה מפורשים (לא «נוסיף אחר כך»). כל PR שמשנה זרימה חייב לכלול את האירועים הרלוונטיים או לעדכן את רשימת החוב במפורש — ראו מסמך אנטי־חוב.

## 4. עקרון מעבר: שני מצבים, מקור אמת אחד

במהלך המעבר מותרת תקופת ביניים קצרה שבה:

- מסלול מהיר = ברירת מחדל ל־UI.
- מסלול מלא (צ׳אט + כיוונים + הגדרות) = זמין דרך «רוצה שליטה מלאה».

אסור:

- שני רכיבי אשף מקבילים שלא חולקים state.
- שני חוזי `generate` שונים בלי שכבת תאימות.
- כפתור שמוביל ל־`alert` או למסך ריק.

כל פיצ׳ר במצב «עדיין לא» — **מוסתר**, לא «בקרוב» במסלול הראשי.
