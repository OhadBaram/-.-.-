# חוזי נתונים וכללי אנטי־חוב

מטרת המסמך: שכל שינוי בזרימה יגיע **שלם** — UI, ולידציה, API, אנליטיקה, והסרת נתיבים מתים — בלי stubs ובלי «נשלים אחר כך» שקטים.

---

## 1. חוזה יצירה מורחב (יעד)

הרחבה של

`generateCarouselSchema`

ב־

`src/lib/validations.ts`

עקרונות:

- שדות חדשים **אופציונליים** בתחילה עם ברירות מחדל — לא שוברים לקוחות ישנים.
- ברירות המחדל מתועדות כאן ובקוד (מקור אמת אחד).

### שדות חדשים מוצעים

| שדה | טיפוס | ברירת מחדל | חובה ב־UI מהיר |
|-----|--------|------------|----------------|
| `publishTarget` | `'instagram' \| 'linkedin'` | `'instagram'` | כן (או דילוג→ברירת מחדל) |
| `coverImageDataUrl` | `string` (data URL) אופציונלי | אין | לא |
| `coverImageApplyTo` | `'first' \| 'first_and_image_slots'` | `'first'` | מוסתר בשלב 1 |
| `flowVariant` | `'fast' \| 'full'` | `'fast'` | אנליטיקה / דיבוג |

### מה לא להכניס לחוזה עד שיש מימוש

| שדה | סיבה |
|-----|------|
| `screenshotUrls` | ה־stub `screenshots` עדיין לא מומש |
| `aiImagePrompt` | אין backend אמיתי |
| `publishNow` | אין חיבור פלטפורמה |

### תאימות לאחור

- בקשות בלי `publishTarget` → מתנהגות כ־`instagram`.
- בקשות בלי תמונה → כמו היום.
- תשובת API ממשיכה להחזיר `slides`, `caption`, `hashtags`, `explanation`, `wizardMeta`.
- `explanation` נשאר בשדה התשובה גם אם ה־UI כבר לא חוסם עליו.

### שיוך תמונה בשרת מול לקוח

**שלב A (מומלץ ראשון, פחות תשתית):**  
הלקוח שולח `coverImageDataUrl`; השרת **אינו חייב** לאחסן. אחרי קבלת `slides`, הלקוח מדביק את התמונה לשקף לפי `coverImageApplyTo`.  
יתרון: בלי אחסון. חיסרון: body גדול; חובה מגבלת גודל.

**שלב B (אחרי שלב A יציב):**  
העלאה לאובייקט סטורג׳ → `coverImageUrl` קצר בחוזה. מיגרציה מתועדת; הסרת data URL מהחוזה או תמיכה בשניהם לתקופה מוגבלת עם תאריך הסרה.

כלל אנטי־חוב: לא להתחיל שלב B «באמצע» שלב A באותו PR.

## 2. מיפוי פורמט מרכזי

קובץ יחיד מוצע:

`src/lib/publish-target.ts`

אחריותו:

```
publishTarget
  → canvasWidth / canvasHeight (או יחס)
  → exportPrimary: 'zip' | 'pdf'
  → exportSecondary: 'zip' | 'pdf'
  → labels בעברית ל־CTA
  → (עתידי) בחירת תבניות ברירת מחדל
```

כל קריאה ל־`1080` / `1350` בעורך ובייצוא צריכה לעבור דרך המיפוי — או להישאר קבועים רק אם המיפוי מחזיר את אותם ערכים במפורש לשלב הראשון.

### שלב ראשון מקובל בלי שינוי מימדים

אם בשלב מוקדם `instagram` ו־`linkedin` עדיין חולקים

`1080×1350`

זה מותר **רק אם**:

1. המיפוי המרכזי קיים ומחזיר ערכים זהים במכוון.
2. יש כרטיס חוב פתוח במסמך זה / ב־PR plan עם יעד לשנות יחס לאינסטגרם.
3. ה־UI כבר מציג CTA לפי יעד (הבדל תוכן, לא רק תווית מזויפת בלי שדה יעד).

אסור: לשנות תוויות כפתור בלי שדה `publishTarget` ב־state.

## 4. הסרת stubs — מדיניות

| פריט | פעולה נדרשת | מתי |
|------|-------------|-----|
| `visualStyle: 'screenshots'` | הסרה מ־UI; הסרה מ־enum **או** הפיכה לערך פנימי לא־סלקטבילי עם מיגרציה | באותו PR שמארגן מחדש את בחירת הסגנון במסלול המהיר/מלא |
| כפתור «תמונה ב-AI (פרו)» | הסרה או `feature flag` כבוי כברירת מחדל בלי רינדור | ב־PR של רכיב התמונה |
| מסך «החבילה מוכנה» כשער | הסרה או דגל `GATE_PACKAGE_SUMMARY=false` כברירת מחדל; נתיב ישן נמחק אחרי אימות | PR ייעודי קטן |
| הודעות «בקרוב» במסלול הראשי | אפס | מתמשך — שינוי שמכניס «בקרוב» נדחה ב־review |

כלל גולדן:

> פיצ׳ר לא מוכן = לא מוצג. לא «בקרוב». לא alert. לא stub ב־enum שמופיע למשתמש.

## 5. מצב לקוח —

`CarouselCreator`

### היום (מפושט)

```
slides / explanation / isApproved / showWizardOverDraft / wizardMeta / brandPalette
```

### יעד

```
slides
caption / hashtags          — תמיד נגישים בעורך
wizardMeta
brandPalette
publishTarget
coverImage (אופציונלי, לפני/בזמן create)
showWizardOverDraft         — נשמר
packageSummaryDismissed     — במקום isApproved כשער
flowVariant                 — 'fast' | 'full'
```

`isApproved` כשער מסך ביניים → מיועד להסרה. אם נשאר זמנית:

- ברירת מחדל אחרי generate מוצלח = מאושר.
- מסך הסיכום רק אם דגל מפורש דולק.

## 9. Definition of Done — כללי לכל שינוי

שינוי בזרימה נחשב «סגור» רק אם:

1. יש התאמה בין UI לחוזה API (אין שדה UI בלי schema ולהפך במסלול הראשי).
2. אין CTA שמוביל למבוי סתום.
3. נתיב ישן שיועד להסרה אכן הוסר או מאחורי דגל עם תאריך הסרה.
4. אנליטיקה רלוונטית מעודכנת או סומנה במפורש כ־DEBT עם יעד.
5. תיאור ה־PR מצביע על As-Is / To-Be של אותו שינוי בלבד.
6. אין קוד מת שהושאר «למקרה ש».
