# מפרט מסכים — מסלול מהיר

Wireframes טקסטואליים, מיקרו־קופי, מצבי קצה, והתנהגות מול המצב הקיים בכל מסך.

מוסכמות:

- **CTA ראשי** = פעולה אחת ברורה למסך.
- **RTL** מלא; מונחים טכניים באנגלית מופיעים בתיעוד זה בשורות נפרדות כשצריך דיוק מימושי.
- מובייל־ראשון אלא אם צוין אחרת.

---

## מפה כללית

```
S0  יעד פרסום          (ניתן לדלג → ברירת מחדל instagram)
S1  נושא               (חובה)
S2  תמונה אופציונלית   (ניתן לדלג)
S3  טעינת יצירה        (Skeleton — קיים)
S4  עורך               (כניסה ישירה; באנר חד־פעמי)
S5  הורדה / אחרי הצלחה (CTA לפי יעד + הזמנת מותג)
```

מסלול משני (לא חוסם):

```
S1b  עזרה לנסח (צ׳אט) — חוזר ל־S1 עם נושא ממולא
S1c  שליטה מלאה — הגדרות + כיוונים (האשף הקיים, מאורגן מחדש)
```

---

## S0 — בחירת יעד פרסום

### מצב קיים

אין מסך כזה. היעד משתמע מכפתורי הורדה בעורך בלבד.

### מצב סופי

מסך קצר או שלב עליון באשף המהיר. בחירה נשמרת ב־session של היצירה ובחוזה ה־generate.

### Wireframe

```
┌─────────────────────────────────────┐
│  איפה תפרסמו את הקרוסלה?            │
│  נכוון פורמט והורדה. אפשר לשנות     │
│  אחר כך.                            │
│                                     │
│  ┌──────────────┐ ┌──────────────┐  │
│  │ אינסטגרם     │ │ לינקדאין     │  │
│  │ שקפים כתמונות│ │ מסמך PDF     │  │
│  │ ויזואלי, קצב │ │ מקצועי, קריא │  │
│  └──────────────┘ └──────────────┘  │
│                                     │
│  [ עדיין לא בטוחים — אינסטגרם ]     │
└─────────────────────────────────────┘
```

### מיקרו־קופי

| אלמנט | טקסט |
|--------|------|
| כותרת | איפה תפרסמו את הקרוסלה? |
| משנה | נכוון את הפורמט ואת ההורדה בהתאם. אפשר לשנות אחר כך. |
| כרטיס IG | אינסטגרם · שקפים כתמונות |
| כרטיס LI | לינקדאין · מסמך מקצועי |
| דילוג | עדיין לא בטוחים — נתחיל באינסטגרם |

### כללים

- בחירה = מעבר מיידי ל־S1 (בלי כפתור «המשך» נוסף).
- דילוג = `publishTarget: 'instagram'`.
- בעורך: אפשר לשנות יעד מסרגל עליון; משנה CTA הורדה ראשי ויחס קנבס לפי מיפוי מרכזי.

### מצבי קצה

| מקרה | התנהגות |
|------|---------|
| משתמש חוזר מאשף מלא | שומרים יעד אם כבר נבחר |
| שינוי יעד אחרי יצירה | לא מוחקים תמונות/טקסט; רינדור מחדש לפי יחס חדש |

### אנטי־חוב

- לא להוסיף יעד בלי לעדכן את מיפוי המימדים המרכזי.
- לא להשאיר כפתורי ZIP/PDF עם תוויות זהות בלי היררכיית CTA.

## S1 — נושא (ליבת המסלול המהיר)

### מצב קיים

צ׳אט דו־כיווני כברירת מחדל + פאזת intake; «המשך» מוביל להמלצות/כיוונים. בנייד היו חיכוכים בין מיקום הכיוונים לבין כפתור היצירה (טופל בנפרד).

### מצב סופי

שדה נושא גדול הוא הגיבור. צ׳אט אינו חומה.

### Wireframe (מובייל)

```
┌─────────────────────────────────────┐
│  שלב 1 מתוך 3 · נושא                │
│                                     │
│  על מה הקרוסלה?                     │
│  ┌───────────────────────────────┐  │
│  │ למשל: 5 טעויות שמרחיקות…     │  │
│  └───────────────────────────────┘  │
│                                     │
│  הצעות מהירות:                      │
│  [טיפים לשבוע] [לפני/אחרי]         │
│  [טעות נפוצה] [שאלות־תשובות]       │
│                                     │
│  רוצה עזרה לנסח?                    │
│  שליטה מלאה (סגנון, כיוון, מספר)   │
│                                     │
│  [         המשך         ]           │
└─────────────────────────────────────┘
```

### מיקרו־קופי

| אלמנט | טקסט |
|--------|------|
| כותרת | על מה הקרוסלה? |
| placeholder | למשל: 5 טעויות שמרחיקות לקוחות מהעסק |
| CTA | המשך |
| משני | רוצה עזרה לנסח? |
| משני 2 | שליטה מלאה |

### כללים

- CTA פעיל רק כשיש נושא לא־ריק (אחרי trim).
- פרומפט מהיר ממלא את השדה (ניתן לעריכה) — לא שולח מיד ל־API.
- «עזרה לנסח» פותח את צ׳אט קיים כשכבה/מסך; בסיום מחזיר נושא (ואופציונלית audience/goal) ל־S1.
- «שליטה מלאה» פותח את זרימת ההגדרות+כיוונים הקיימת, עם אותם חוזי API — בלי אשף שני.

### ברירות מחדל אוטומטיות במסלול המהיר

כשלא נכנסים ל«שליטה מלאה»:

| שדה | ברירת מחדל |
|-----|------------|
| `slideCount` | 7 (קיים) |
| `density` | `standard` |
| `visualStyle` | `minimal` |
| `useRecommendedStructure` | `true` |
| `narrativeDirection` | השרת בוחר כיוון יחיד שקט (או מבנה מומלץ בלי UI בחירה) |

### אנטי־חוב

- לא לשכפל את לוגיקת ה־wizard-chat במסלול המהיר.
- מסלול מלא חייב לקרוא לאותו `onSubmit` / אותו schema מורחב.

## S1b — עזרה לנסח (צ׳אט)

### מצב קיים

הצ׳אט הוא המסלול הראשי.

### מצב סופי

כלי עזר. אותו API:

`/api/wizard-chat`

### UI

- כותרת: «בואו ננסח יחד»
- יציאה ברורה: «השתמש בנושא הזה» / «חזרה»
- לא לכפות הגעה ל־`ready_for_directions` לפני חזרה למסלול המהיר; אם המשתמש רוצה כיוונים — זה «שליטה מלאה».

### אנטי־חוב

- לא ליצור צ׳אט חדש או פרומפטים סותרים.
- אם משנים פאזות ב־API — לעדכן גם מסלול מלא וגם מסלול עזרה.

## S1c — שליטה מלאה

### מצב קיים

פאנל הגדרות סופיות + כיווני תוכן + יצירה.

### מצב סופי

אותו תוכן, מאורגן כמסלול משני:

1. הגדרות (שקפים, צפיפות, סגנון, פלטה)
2. כיוון תוכן (אם רלוונטי)
3. תמונה אופציונלית (אותו רכיב כמו S2)
4. יצירה

להסיר מהמסלול המלא:

- אפשרות `screenshots` (stub) — עד מימוש אמיתי.

### אנטי־חוב

- הסרת stub מה־UI **ומה־enum** באותו שינוי, או השארת הערך רק בצד שרת לתאימות לאחור עם מיגרציה מתועדת — לא UI מת.

## S2 — תמונה אחת (אופציונלי)

### מצב קיים

אין העלאה באשף. בעורך בלבד דרך

`SlideEditor`

עם כפתור «תמונה ב-AI (פרו)» שמציג alert.

### מצב סופי

### כללי שיוך אחרי יצירה

| מצב | התנהגות |
|-----|---------|
| יש תמונה | `slides[0].imageUrl` = התמונה; תבנית שקף 0 עוברת למשפחת `image-*` לפי מדיניות קיימת |
| אופציה עתידית | צ׳יפ «החל על כל שקפי התמונה» — רק אחרי שהבסיס יציב |
| דילוג | שקפי תמונה נשארים עם placeholder לחיץ |

### מגבלות קובץ (לחייב באותו שינוי UI+ולידציה)

להגדיר במקום אחד משותף (קבועים + הודעות שגיאה):

- סוגים מותרים: תמונות נפוצות לדפדפן
- גודל מקסימלי סביר ל־base64 בזיכרון (או מעבר להעלאת אחסון בשלב נפרד — ראו חוזים)
- הודעת שגיאה בעברית ברורה

### אנטי־חוב

- רכיב העלאה **אחד** משותף לאשף ולעורך (לא שני `FileReader` מפוזרים עם כללים שונים).
- כפתור AI תמונה: להסתיר עד מימוש; לא alert.
- אם נשארים עם base64 בלבד בשלב הראשון — לתעד זאת כהחלטה מודעת עם מגבלת גודל ואנליטיקה; שלב אחסון = PR נפרד עם חוזה מלא.

## S4 — עורך (כניסה ישירה)

### מצב קיים

אם יש `explanation` → מסך «החבילה מוכנה» עד אישור. אחר כך עורך. תמונה דרך סיידבר/SlideEditor. מובייל: לשוניות תצוגה/עריכה (בסניף נפרד).

### מצב סופי

1. אחרי generate מוצלח → `isApproved = true` מיד (או הסרת השער).
2. `explanation`, כיתוב והאשטאגים זמינים במגירה/פאנל «תוכן לפוסט» — לא חוסמים.
3. באנר חד־פעמי (session) בראש:

«החבילה מוכנה. לחצו על אזור התמונה להחלפה · ההורדה למעלה.»

4. לחיצה על אזור תמונה/placeholder בקנבס → אותו רכיב העלאה משותף.
5. מובייל: תצוגה מקדימה כברירת מחדל; כפתור «החלף תמונה» גלוי כשאין תמונה בשקף הפעיל.

### Wireframe דסקטופ (היררכיה)

```
┌──────────────────────────────────────────────────────────┐
│ ← אשף   יעד: אינסטגרם ▾   שקף 1/7    [הורד לאינסטגרם]   │
│                                          [PDF ללינקדאין] │
├────────┬───────────────────────────────────┬─────────────┤
│ שקפים  │                                   │ טקסט שקף    │
│ 1 ●    │         קנבס (גיבור)              │ [textarea]  │
│ 2      │    לחיצה על תמונה = החלפה         │ תמונה       │
│ 3      │                                   │ [החלף]      │
│ +      │                                   │ מתקדם ▸     │
└────────┴───────────────────────────────────┴─────────────┘
│ כיתוב והאשטאגים ▸ (מגירה)                                │
└──────────────────────────────────────────────────────────┘
```

### Placeholder לחיץ — מפרט התנהגות

| מצב | תצוגה על הקנבס | פעולה |
|-----|----------------|--------|
| אין תמונה | אזור מקווקו + «לחצו להוספת תמונה» (במקום טקסט סטטי בלבד) | פותח קלט קובץ |
| יש תמונה | התמונה כרגיל | לחיצה ארוכה / כפתור קטן «החלף» — לא לאבד בטעות |
| העלאה נכשלה | הודעה קצרה מעל הקנבס | השארת מצב קודם |

מימוש מומלץ בלי חוב:

- שכבת hit-area מעל הקנבס באזור התמונה לפי תבנית, **או**
- כפתור צף מעוגן לשקף הפעיל שמפעיל את אותו handler כמו ב־SlideEditor.

יש לבחור גישה אחת ולתעד אותה ב־PR; לא שתי דרכים סותרות.

### אנטי־חוב

- מסך «החבילה מוכנה» כשער: להסיר או להפוך לאופציונלי מאחורי דגל — לא להשאיר שני נתיבים לנצח.
- כיתוב/האשטאגים חייבים להישאר נגישים אחרי הסרת השער (רגרסיה פונקציונלית אסורה).
- תלות ב־PR מובייל לתצוגה מקדימה: לא לשחרר שינויי עורך מובייל נוספים לפני שתצוגה מקדימה יציבה ב־main.

## S5 — הורדה ואחרי הצלחה

### מצב קיים

שני כפתורים בסיידבר: ZIP ו־PDF, בלי קשר ליעד מפורש.

### מצב סופי

| `publishTarget` | CTA ראשי | CTA משני |
|-----------------|----------|----------|
| `instagram` | הורידו שקפים לאינסטגרם (ZIP) | הורידו PDF ללינקדאין |

«רוצים שהקרוסלה הבאה תיראה כמו המותג שלכם?»  
[שמרו צבעי מותג] [לא עכשיו]

### אנטי־חוב

- לא לחבר «פרסום ישיר לאינסטגרם» עד שיש OAuth אמיתי.
- אירוע אנליטיקה `first_download` נשלח פעם אחת לכל חבילה.

## אונבורדינג פרופיל — מדיניות מעבר

### מצב קיים

חובה `name` + `phone` לפני כל ה־dashboard; אחר כך עוד שלבי אתר/ניתוח.

### מצב סופי (מדורג)

**שלב מוצר A (מוקדם):**  
לא לשבור את שער הטלפון אם הוא דרישת עסק/תפעול — אבל לדחוף את שלבי האתר/ניתוח **אחרי** הורדה ראשונה או כאופציה בהגדרות.

**שלב מוצר B (אחרי מדידה):**  
לבחון צמצום שער הכניסה למינימום משפטי/עסקי בלבד.

המפרט הנוכחי **אינו** דורש הסרת טלפון ב־PR הראשון. הוא דורש:

- הפרדה ברורה בין «חובה לשימוש» לבין «העשרת מותג».
- לא לחסום יצירה בשל כשל בניתוח אתר.

### אנטי־חוב

- לא לבנות אונבורדינג מותג שני במקביל לעמוד הקיים; להרחיב את הקיים או להעביר שלבים.
